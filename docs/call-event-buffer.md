# Bounded local call event buffer

This candidate adds a 128-entry volatile pull buffer bound to one trusted LocalDispatcher, including ActorID, TargetID, ProviderID, SessionID and Generation. It installs no handler, socket listener, MCP route or provider enrollment. CallEventBuffer.Invoke explicitly binds one authorized operation to this buffer through the ordinary dispatcher. The call provider maps owned Manager observations into the redacted buffer; ordinary dispatcher calls have no publisher. No network event endpoint is registered and synthetic lifecycle tests do not prove physical call behavior.

Only sequence, call ID, whitelisted state and update timestamp are stored. Validated short ID/state strings are cloned before retention so a short substring cannot pin an arbitrarily large producer backing string; this bounds owned field storage, not caller-held pages or garbage awaiting collection. Numbers, media paths, raw errors and arbitrary payloads have no fields. Append is a trusted in-process producer seam, never a remote API; producers must derive binding and call ID from their owned operation. The same strings from a remote caller are not authentication.

Every read checks live root environment, provider identity, full binding and authenticated originating call permission before and after copying a bounded page. Event capability support is declared separately from command readiness. Busy calls may expose authorized events without admitting a second call; missing event support fails closed. All authorizer/provider callbacks are outside the ring mutex. External revocation is not atomic with a returned value, so this is not a retroactive guarantee for data already returned.

Overwrite reports the lost sequence count. Pagination uses a per-buffer random stream namespace, not a credential; foreign-stream and future cursors fail. The all-zero cursor starts a fresh read, still requiring full authorization. Overflow cannot wrap. Buffer Close clears storage and permanently rejects reads/writes. Dispatcher Close denies subsequent reads/writes as well, but the owner must also Close/release the buffer to clear its storage immediately. Reconnection uses a new dispatcher/buffer; old cursors do not migrate.

## Owned lifecycle publisher

RunMediaContextObserved is an explicit per-operation observation hook. The initial dialing, waiting-for-answer, playing and terminal states are copied without number/media/error fields and sent outside the Manager mutex. The terminal observation occurs only after the owned path's media exit, physical cleanup attempt and existing terminal-history call; failure to confirm cleanup still reports failure/quarantine, never fabricated success. These are volatile runtime observations, not a carrier report or persisted-history guarantee.

A nil observer leaves the prior owned path semantics. History nil/Get/List behavior and the legacy asynchronous path are unchanged. The hook is held in the owned context, not a global Manager callback, so later operations do not inherit an old actor's publisher. A slow trusted observer holds the operation busy; no unbounded asynchronous queue hides it. Observer panic is isolated with a generic log line so it cannot skip cleanup or leak raw panic content. Buffer or session closure rejects late writes; skipped observations are not retroactively synthesized. The lost count denotes ring overwrite only, not a guarantee of complete lifecycle delivery.

No production event transport, enrollment, audio driver, SMS or real-device call acceptance is claimed. The original missing audio dependencies remain a separate integration condition.
