# Communications provider identity boundary

Private provider-session registration rejects empty, oversized, invalid UTF-8 or malformed identifiers before calling its trusted verifier. The same identifier contract applies to principal actor/token identifiers and newly generated session identifiers. Failed replacement identity generation leaves the old binding intact. Valid Unicode identifiers remain supported; no normalization or identity rewriting is introduced.

This does not implement a production verifier or enable communications. Ordinary Agent enrollment, AgentHello platform metadata and a claimed root flag are not proof of a privileged Android service. A production verifier must bind protected provider identity and fresh possession evidence to the exact connection and agent/target/provider tuple, and reject replay across these scopes. Public-key possession alone is not proof of Android UID 0; trusted provisioning and a real process-identity source are still required. Session UUID/generation is created after verification and cannot serve as a registration challenge or its replay protection.

Offline tests cover malformed candidate identities before verifier calls, invalid principals, invalid new session IDs, preservation of the existing connection after failed replacement, and valid Unicode identities. Selected server communications tests and full protocol/serviceplugins packages passed with the race detector and count=3. The old helper fails the new boundary tests. This is not a full server, P2P, Android/root, audio/call/SMS or production acceptance result. All communications routes remain disabled and no new provider registration transport is exposed.
